# 중복 발표 요청 안내 문구 구분

2026-11-05. 사용자가 선택한 동작: 첫 발표가 끝날 때까지 기다린 뒤 이미 발표됐음을 안내한다.

| 요청 | HTTP | message | 추가 알림 |
|---|---|---|---|
| 최초 발표 | 200 | 지원 결과 처리 완료 | 최초 대상에만 전송 |
| 모든 대상이 이미 발표된 재요청 | 200 | 이미 발표했습니다 | 없음 |
| 신규 발표 대상과 이미 발표된 대상이 섞인 요청 | 200 | 지원 결과 처리 완료 | 신규 대상만 전송 |
| 심사 WAIT 또는 빈 요청 | 200 | 지원 결과 처리 완료 | 없음 |

락을 획득한 서비스 트랜잭션 안에서 모든 대상이 이미 발표됐는지 계산한다. WAIT는 미발표이므로 `이미 발표했습니다`로 안내하지 않는다. 컨트롤러는 별도 조회 없이 이 결과에 따라 문구만 바꾼다.

동시 요청 10개의 기대 결과: `지원 결과 처리 완료` 1개, `이미 발표했습니다` 9개. HTTP는 모두 200이며 회원 1행·FCM 요청 1회를 유지한다. 요청 도착 순서에 따라 어떤 요청이 최초 처리될지는 달라진다.

사용자의 직접 실행과 구분해 AI 실행 로그를 `evidence/week10/publication-response/`에 보관한다. 이전 중복 방지 수정 결과는 덮어쓰지 않는다. RED 테스트 12개가 기존 동일 문구 때문에 실패하는 것을 확인한 뒤 수정했다. 최종 GREEN 결과는 같은 폴더의 green.log 및 JUnit 결과를 확인한다.

알림 전송 실패 후 복구, 처리 중 즉시 거절, 발표 후 상태 수정 정책은 이번 변경 범위 밖이다. JSON 필드 구조와 상태 코드는 유지하지만 기존 계약의 성공 message에 안내 문구가 추가되므로 문자열로 성공 여부를 비교하는 클라이언트는 확인이 필요하다.

검증 결과: 전체 88개 통과(재현·회귀 83개 + 기존 단위 5개), 실패/건너뜀 0. JAR 빌드 성공. 동시 발표 10회 반복에서 매회 완료 문구 1개·이미 발표 문구 9개, 회원 1행·FCM 요청 1회를 확인했다. 순차 재요청·혼합 대상·WAIT·빈 요청도 통과했다.
