# 중복 발표 요청 응답 구분

사용자 선택: 첫 발표 요청의 트랜잭션이 끝날 때까지 기다린 뒤, 이미 발표된 요청에 안내 메시지를 반환한다. 처리 중 즉시 거절하는 NOWAIT 방식은 사용하지 않는다.

- 락·회원 Unique 제약·HTTP 200·ApiResponse의 JSON 구조는 유지한다.
- 비어 있지 않은 요청의 모든 대상이 이미 공개된 경우 `이미 발표했습니다`를 반환한다.
- 신규 발표가 하나라도 포함되면 기존 `지원 결과 처리 완료`를 유지한다. 아직 심사 WAIT인 지원자나 빈 요청을 이미 발표됐다고 안내하지 않는다.
- 결과 구분은 락을 획득한 동일 서비스 트랜잭션에서 계산한다. 컨트롤러에서 별도 재조회하지 않는다.
- 테스트: 순차 재요청 메시지, 동시 10개 요청 중 최초 문구 1개·이미 발표 문구 9개, 기존 회원/FCM 각 1개 유지, 혼합·WAIT·빈 요청 문구.
- 검증 순서: 응답 구분 테스트의 RED → 서비스 반환값과 컨트롤러 문구 분기 → 전체 회귀 GREEN.
